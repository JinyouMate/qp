# 第 5 步 · 留资表单 + Supabase + Resend 通知

---

## 1. 表单组件

**文件**：`components/site/lead-form.tsx`（通用）、`components/site/contact-form.tsx`（`/contact` 页专用）

技术：**React Hook Form + Zod** 校验，字段级错误提示，提交态转圈。

### 字段与校验规则

| 字段 | 类型 | 规则 |
|---|---|---|
| 姓名 `name` | 文本 | 必填，1–50 字 |
| 微信/手机 `contact` | 文本 | 必填，1–80 字 |
| 身份 `role` | 下拉 | 必选：修理厂 / 汽配商 / 平台企业 / AI公司 / 其他 |
| 需求 `demand` | 下拉 | 必选：知识库 / 数据产品 / SOP / 报告 / 课程 / 咨询 / SaaS / AI合作 |
| 具体问题描述 `description` | 多行 | 选填，≤2000 字（写了回得更准） |
| 同意隐私政策 `consent` | 复选 | **必须勾选**，否则拦截提交 |
| UTM（隐藏） | 自动 | `utm_*` + `referrer` + `landing` + `channel`，用户不可见 |

### 深链预填

URL 参数自动选中下拉：`/contact?role=汽配商&demand=课程&intent=asset`
所有站内 CTA 都带这些参数，用户点进来时表单已选好，转化率显著更高。

### 提交流程

```
点击提交 → Zod 校验（不过则字段级红字）
         → POST /api/leads
         → 埋点 form_submit
         → 成功态：「加微信后回复【汽配数据】，领取资料」
         → 1.4 秒后 router.push("/wechat?from=contact")
         → 加微页顶部绿条提示 + 二维码
```

失败处理：红色提示条 + 保留已填内容，不丢数据。

## 2. 接口 `POST /api/leads`

**文件**：`app/api/leads/route.ts`（`runtime = "nodejs"`）

```ts
const LeadSchema = z.object({
  name: z.string().min(1).max(50),
  contact: z.string().min(1).max(80),
  role: z.string().min(1).max(30),
  demand: z.string().min(1).max(30),
  description: z.string().max(2000).optional(),
  consent: z.boolean().refine((v) => v === true),   // 强制同意
  utm: z.record(z.string()).optional(),
  channel: z.enum([...]).optional(),                 // 8 个渠道枚举，非法值 422
  source: z.string().max(500).optional(),
});
```

处理顺序：
1. `safeParse` 失败 → `422` + `issues`（字段级错误）
2. 写 Supabase `leads` 表（`status = "new"`）
3. **并行**发 Resend 邮件 + 飞书机器人（失败不影响用户看到成功）
4. 返回 `{ ok, stored, mode, notify: { email, feishu } }`

**降级**：未配 Supabase 时 `stored=false, mode="demo"`，线索只打服务端日志，页面照常成功。

## 3. Supabase 建表

### 3.1 执行迁移（按顺序）

在 Supabase 控制台 → **SQL Editor** → 新建查询 → 依次粘贴执行：

| 顺序 | 文件 | 内容 |
|---|---|---|
| 1 | `supabase/migrations/0001_init.sql` | 5 张表（leads / products / contents / cases / partners）+ RLS + 产品种子数据 |
| 2 | `0002_leads_source.sql` | `leads.source` 列（落地页 URL） |
| 3 | `0003_tier_and_channel.sql` | `products.tier`（四档）+ `leads.channel`（来源渠道）+ 工具包种子数据 + 索引 |
| 4 | `0004_events.sql` | `events` 表（埋点事件）+ 索引 + RLS 策略 |

> 全部脚本用 `if not exists` / `add column if not exists`，重复执行安全。

### 3.2 leads 表结构

```sql
create table public.leads (
  id          bigint generated by default as identity primary key,
  name        text not null,
  contact     text not null,
  role        text not null,              -- 修理厂/汽配商/平台企业/AI公司/其他
  demand      text not null,              -- 知识库/数据产品/SOP/报告/课程/咨询/SaaS/AI合作
  description text,
  utm         jsonb default '{}'::jsonb,  -- utm_* + referrer + landing
  channel     text not null default 'other',
  source      text,                       -- 落地页 URL
  status      text not null default 'new',-- new/contacted/won/closed
  created_at  timestamptz not null default now()
);
```

### 3.3 安全模型

- 5 张表**全部启用 RLS**，匿名完全不可读写；
- 站点只在**服务端**（API Route）用 service role 写入，前端永远拿不到 key；
- 环境变量 `SUPABASE_SERVICE_ROLE_KEY` **不能加** `NEXT_PUBLIC_` 前缀。

### 3.4 拿到三个值

Supabase 控制台 → Project Settings → API：
- `NEXT_PUBLIC_SUPABASE_URL` = Project URL
- `SUPABASE_SERVICE_ROLE_KEY` = service_role key（**不要泄露**）

## 4. Resend 邮件通知

### 4.1 配置步骤

1. 注册 [resend.com](https://resend.com) → API Keys → Create（`re_xxxxxx`）
2. **验证发信域名**：Domains → Add Domain → 按提示加 SPF / DKIM / DMARC 三条 DNS 记录
   （未验证域名只能发到你自己的注册邮箱）
3. 填入环境变量：

```bash
RESEND_API_KEY=re_xxxxxx
RESEND_FROM_EMAIL="汽配知识局 <no-reply@yourdomain.com>"
LEAD_NOTIFY_EMAIL=you@yourdomain.com
```

### 4.2 邮件内容（自动生成）

```
标题：【新线索·抖音】张三 · 修理厂 · SOP
正文：姓名 / 联系方式 / 身份 / 需求 / 来源渠道 / 描述 / 落地页 / UTM / 时间（北京时间）
```

### 4.3 飞书机器人（可选但推荐）

群设置 → 群机器人 → 添加自定义机器人 → 复制 Webhook：

```bash
FEISHU_WEBHOOK_URL=https://open.feishu.cn/open-apis/bot/v2/hook/xxxxxx
```

## 6. 本地自测

```bash
# 正常提交（channel 合法）
curl -X POST http://localhost:3111/api/leads -H 'Content-Type: application/json' \
  -d '{"name":"张三","contact":"wx001","role":"修理厂","demand":"SOP",
       "description":"要选品SOP","consent":true,"channel":"douyin",
       "utm":{"utm_source":"douyin"}}'
# → {"ok":true,"stored":true,"mode":"supabase","notify":{"email":true,"feishu":true}}

# 非法渠道 → 422
curl -o /dev/null -w '%{http_code}' -X POST http://localhost:3111/api/leads \
  -H 'Content-Type: application/json' \
  -d '{"name":"x","contact":"1","role":"r","demand":"d","consent":true,"channel":"tiktok"}'
# → 422

# 未勾选同意 → 422
curl -o /dev/null -w '%{http_code}' -X POST http://localhost:3111/api/leads \
  -H 'Content-Type: application/json' -d '{"name":"x","contact":"1","role":"r","demand":"d","consent":false}'
# → 422
```

> 本地测端口记得加 `--noproxy '*'`（本机 curl 默认走代理会连不上）。

## 7. 常见问题

| 问题 | 排查 |
|---|---|
| 提交成功但 Supabase 没数据 | 看接口返回的 `stored`；`false` 说明环境变量没生效，重启 dev server |
| 邮件没收到 | 域名未验证（只能发注册邮箱）；检查 Resend 后台 Logs |
| 飞书没消息 | webhook 是否正确、机器人是否被移出群 |
| 写入报 RLS 错误 | 必须用 service_role key，不是 anon key |
| `source` 列不存在 | 漏执行 `0002_leads_source.sql` |
