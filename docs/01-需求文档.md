# 汽配知识局官网 · 需求文档

> 版本 v1.0 ｜ 技术栈：Next.js 14 App Router + TypeScript + Tailwind + Supabase
> 本文只定义「要做什么」，不含代码。实现细节见 `03`~`09` 号文档。

---

## 1. 项目定位

这不是电商站，也不是企业展示站。它是**汽配行业知识资产运营商**的官网，承担四个职能：

| 职能 | 含义 | 可验收标准 |
|---|---|---|
| **信任中枢** | 让访客在 30 秒内判断「这家靠不靠谱」 | 首屏可见：身份说明、积累数据、交付方式、合规声明 |
| **路由中枢** | 让不同需求的人 1 次点击找到对应入口 | 四类访客各有独立入口卡，直达对应产品档位 |
| **留资收口** | 所有公域流量最终落到表单 / 微信 / 私域 | 每页底部 + 侧边固定入口；第三方跳转前必过拦截 |
| **品牌锚点** | 所有平台账号的统一官方源头 | 全网同名，所有外链从官网发出并带 UTM |

### 1.1 一句话主张
**汽配行业知识资产运营商——把隐性知识变成可交易资产。**（副标题：从数据到决策，从知识到工具）

### 1.2 明确不做
- 不做支付、购物车、复杂会员系统（成交与交付全在第三方平台）
- 不做代运营、不卖货、不碰交易资金
- 不让公域内容直接跳第三方成交页

## 2. 商业模式与流量路径

### 2.1 唯一正确的流量路径

```
公域内容（抖音/视频号/知乎/公众号/B站/搜索）
        ↓
   官网 / 私域        ← 留资发生在这里
        ↓
第三方平台成交交付     ← 小鹅通 / 知识星球 / Baklib / 飞书 / 合作方平台
        ↓
   私域复购与转介绍
        ↓
   官网品牌资产沉淀
```

**红线**：任何从内容平台直达第三方成交页的链路都必须被拦截。官网是所有成交的前置节点。

### 2.2 第三方平台分工

| 平台 | 承载 |
|---|---|
| 小鹅通 | 培训课程、工具包（99–499 档、年卡） |
| 知识星球 | 付费社群、闭门问答 |
| Baklib / 飞书 / Notion | 知识库、SOP、模板查阅 |
| 飞书 | 完整报告、订阅数据看板、咨询预约 |
| 合作方平台 | SaaS 合作、AI 数据标注与模型训练 |

### 2.3 产品阶梯（四档）

| 档位 | 价格带 | 目标 | 内容 |
|---|---|---|---|
| 第 1 档 免费内容 | ¥0 | 认识我们 | 内容 IP、SOP 清单、报告摘要、模板、案例 |
| 第 2 档 工具包 | ¥99–¥499 | 解决一个具体问题 | 选品评分 / 核价毛利 / 适配校验 / 库存周转 |
| 第 3 档 课程·订阅 | ¥999–¥4,999 | 建立体系与持续能力 | 体系课、完整报告、数据订阅、年度通行证 |
| 第 4 档 咨询·内训 | ¥10,000 起 | 解决你自己的问题 | 咨询方案、企业内训、SaaS 合作、AI 数据合作 |

## 3. 目标用户（四类入口）

| 编号 | 身份 | 核心诉求 | 首选入口 | 推荐路径 |
|---|---|---|---|---|
| P1 | 修理厂 / 经销商 | 想解决一个具体问题 | 首页 P1 卡 | 免费 SOP → 工具包 → 咨询 |
| P2 | 汽配商 / 从业者 | 想系统学习 | 首页 P2 卡 | 知识库 → 课程 → 年度通行证 |
| P3 | 平台 / 企业 | 想合作数据产品 | 首页 P3 卡 | 报告 → 数据订阅 → 咨询 |
| P4 | AI 公司 | 想合作行业数据、标注规则、评测标准 | 首页 P4 卡 | AI 数据合作（需签 DPA） |

## 5. 功能需求

### FR-1 留资（最高优先级）

| 编号 | 需求 | 验收标准 |
|---|---|---|
| FR-1.1 | 表单字段：姓名、微信/手机、身份（5 选 1）、需求（8 选 1）、问题描述、UTM 隐藏字段 | 六项齐全，UTM 用户不可见 |
| FR-1.2 | 校验：姓名/联系方式必填，身份/需求必选，**必须勾选隐私政策** | 未勾选无法提交 |
| FR-1.3 | 提交后写入数据库 | Supabase `leads` 表有记录 |
| FR-1.4 | 提交后发邮件 + 飞书通知 | 两条通知都带来源渠道 |
| FR-1.5 | 提交后跳转加微页 | 自动跳 `/wechat?from=contact`，展示二维码 + 回复关键词 |
| FR-1.6 | 深链预填 | URL 带 `role`/`demand`/`intent` 时表单自动选中 |
| FR-1.7 | 每页底部 + 侧边固定留资入口 | 除 `/admin` 外全覆盖；桌面侧边竖排、移动底部条 |

### FR-2 第三方跳转拦截

| 编号 | 需求 | 验收标准 |
|---|---|---|
| FR-2.1 | 所有第三方链接点击前弹轻量留资提示 | 文案含「加微信领取完整资料/优惠链接」 |
| FR-2.2 | 弹窗三个出口 | 加企微（推荐）/ 填表留资 / 已加过继续前往 |
| FR-2.3 | 继续前往时自动附加 UTM | `utm_source=website&utm_medium=product\|gate&utm_campaign=<slug>` |
| FR-2.4 | 不把人堵死 | 始终保留「继续前往」出口 |

### FR-3 私域承接

| 编号 | 需求 | 验收标准 |
|---|---|---|
| FR-3.1 | 加微页展示二维码与回复关键词 | 「加微信后回复【汽配数据】，领取资料」 |
| FR-3.2 | 私域第一句话不是推课 | 页面明示第一句是「你平时遇到这类问题一般怎么处理？」 |
| FR-3.3 | 按身份分社群 | 4 个身份社群矩阵 |

### FR-4 追踪与看板

| 编号 | 需求 | 验收标准 |
|---|---|---|
| FR-4.1 | 来源归类 | 抖音/视频号/知乎/公众号/B站/搜索/直接访问/其他，首触归因 |
| FR-4.2 | 事件追踪 | form_submit / wechat_click / third_party_click / asset_download / consult_click |
| FR-4.3 | 后台看板 | 每日留资数、来源分布、身份分布、事件漏斗与转化率 |
| FR-4.4 | 每周导出 | 按周导出 CSV，按身份与需求分类 |

### FR-5 SEO

| 编号 | 需求 | 验收标准 |
|---|---|---|
| FR-5.1 | 每页独立 title / description / OG 图 | 无重复，OG 图 1200×630 |
| FR-5.2 | 关键词围绕 8 个核心词 | 汽配数据、OE号匹配、VIN解析、新能源汽配、汽配知识库、汽配SOP、汽配出海数据合规、汽配AI数据标注 |
| FR-5.3 | sitemap.xml / robots.txt | 自动生成，robots 禁 `/admin` `/api/` |
| FR-5.4 | Schema.org | Organization / WebSite / Product / Course / FAQPage / BreadcrumbList / Article |
| FR-5.5 | 内容页用 MDX | 利于收录，`/insights` 静态生成 |

### FR-6 AI 问答
后端 API Route 代理，密钥走环境变量，前端不暴露。未配密钥时降级为关键词兜底回复，仍能答疑并引导留资。

## 6. 数据模型

### leads（留资）
`id` / `name` / `contact` / `role` / `demand` / `description` / `utm(jsonb)` / `channel` / `source` / `status(new\|contacted\|won\|closed)` / `created_at`

### products（产品）
`slug` / `name` / `icon` / `layer` / `category` / `tier` / `positioning` / `problem` / `audience` / `deliverable` / `price` / `cta_type(claim\|buy\|consult)` / `third_party_url` / `third_party_platform` / `sort`

> 每个产品必须回答五要素：**适合谁 / 解决什么 / 交付什么 / 怎么收费 / 下一步动作**

### contents / cases / partners / events
内容与案例、案例指标（jsonb）、合作方；`events` 表存站点行为事件供看板算转化率。

## 7. 非功能需求

| 项 | 要求 |
|---|---|
| 移动端 | **移动端优先**，所有页面适配手机；底部安全区留白 |
| 性能 | 静态生成优先，LCP < 2.5s；分析脚本不配则不注入 |
| 降级 | 未配 Supabase 时自动使用兜底数据，站点照常运行 |
| 合规 | 隐私政策、服务条款、版权与数据合规声明第一天就有；AI 数据合作需签 DPA |
| 安全 | 所有写库走服务端 service role；后台接口需 `ADMIN_TOKEN`；AI 密钥不进前端包 |
| 可维护 | 导航/页脚/组件统一维护；改品牌名只需改常量 |

## 8. 品牌与调性

- **调性**：专业、温暖、可信、轻资产、知识型。有案例、有方法，不吹牛。
- **视觉**：绿 / 红 / 橙为主，米白底，少用黑、金、银、纯白；不做冷工业风，不做花哨电商风。
- **图片方向**：真实工作场景、数据截图、课程现场，不用假大空 stock photo。
- **图标**：线性、简洁、统一风格（lucide）。
