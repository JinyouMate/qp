## 一、产品中心 `/products`

**代码**：`app/products/page.tsx`

### 结构

```
PageHero（标签 PRODUCTS）
  ↓
LadderNav      档位锚点 chip（全部 / 免费 / 工具包 / 课程订阅 / 咨询内训）
  ↓
ProductExplorer  四层筛选 Tab（流量层 / 信任层 / 转化层 / 交付层）
  ↓
ProductLadder  四档分段，每段内是产品卡网格
  ↓
LeadSection    底部留资收口
```

### 产品卡六要素（`components/site/product-card.tsx`）

```tsx
<ProductCard product={p} />
```
卡片固定渲染：图标 + 档位徽章 + 层级徽章 → **产品名（链到详情页）** → 一句话定位
→ 解决什么 / 适合谁 / 交付什么 → 怎么收费（砖红价格）→ 下一步动作（`ProductCta`）

### 三类 CTA（`components/site/product-cta.tsx`）

| `cta_type` | 表现 | 去向 |
|---|---|---|
| `claim` 免费领取 | 描边按钮 | `/contact?demand=<需求>&intent=asset`，埋 `asset_download` |
| `consult` 预约咨询 | 砖红按钮 | `/contact?demand=<需求>&intent=consult`，埋 `consult_click` |
| `buy` 去第三方购买 | 暖橙按钮 | 先弹 `ThirdPartyGate`，埋 `third_party_click(stage=intent)` |

## 二、产品详情模板 `/products/[slug]`

**代码**：`app/products/[slug]/page.tsx`（本轮新增）
**内容层**：`lib/product-detail.ts`（本轮新增）

### 2.1 为什么单独拆一层内容

18 个产品共用**一套模板**，内容由产品已有字段推导，不额外维护 18 份文案：

```
pains      痛点       ← product.problem + 档位通用痛点（重点产品可定制）
checklist  交付清单    ← 把 deliverable 按 +、，/ 拆成条目
steps      使用步骤    ← 按 cta_type 三套默认流程
faqs       产品 FAQ    ← 按 cta_type / tier 生成（付款、到账、发票、数据合规）
form/update/timeline ← 交付形式 / 更新频率 / 见效周期
```

**重点产品可覆盖**：在 `lib/product-detail.ts` 的 `PRODUCT_EXTRA` 里按 slug 写定制内容。
已定制：`toolkit-selection` `toolkit-pricing` `toolkit-fitment` `toolkit-inventory` `courses` `ai-data`。
新增产品不写也能出详情页（走默认模板）。

### 2.2 页面结构

| 区块 | 内容 |
|---|---|
| 面包屑 | 首页 / 产品中心 / 产品名（带 BreadcrumbList 结构化数据） |
| Hero 左栏 | 档位+层级徽章、图标、H1、定位、三问快答（适合谁/解决什么/交付什么）、主 CTA + 「加企微先问清楚」、官网不处理支付的说明 |
| Hero 右栏（粘性） | 价格（砖红大字）、交付形式、见效周期、更新频率、交付平台、CTA |
| 正文① | 你会遇到这些情况吗（痛点列表） |
| 正文② | 拿到手是什么（交付清单，两列） |
| 正文③ | 怎么用（编号步骤） |
| 正文④ | 和其他档位怎么选（上下档对比表，本档高亮） |
| 正文⑤ | 关于这个产品，常问的几件事（Faq） |
| 信任补充 | 汽配数据三层校验法（三张卡） |
| 同级推荐 | 同档位其他产品，最多 3 个 |
| 收口 | `LeadSection`（defaultDemand 自动带上该产品需求） |

### 2.3 静态生成与元数据

```tsx
export function generateStaticParams() {
  return FALLBACK_PRODUCTS.map((p) => ({ slug: p.slug }));   // 18 个全部预渲染
}

export async function generateMetadata({ params }): Promise<Metadata> {
  const product = FALLBACK_PRODUCTS.find((p) => p.slug === params.slug);
  return buildMetadata({
    title: product.name,
    description: `${positioning}。适合${audience}；解决：${problem}；交付：${deliverable}；${price}。`,
    path: `/products/${slug}`,
    ogImage: `/og/products-${slug}.png`,     // 每个产品独立 OG 图
    keywords: [name, 档位名, 层级名],
  });
}
```

结构化数据：`productSchema(product)` + `breadcrumbSchema([...])` 一起注入。

### 2.4 新增一个产品只需三步

1. 在 `lib/data.ts` 的 `FALLBACK_PRODUCTS` 加一条（或在 Supabase `products` 表插入）；
2. 跑 `python scripts/gen-og.py` 生成它的 OG 图；
3. 重新构建。详情页、列表页、sitemap 会自动出现，无需改任何组件。

> 想让详情页更具体，再去 `PRODUCT_EXTRA` 里加一份定制内容。

## 四、坑位记录（改动时注意）

> **`"use client"` 文件里导出的普通函数，服务端组件不能直接调用。**
> 原本 `demandForProduct` 定义在 `product-cta.tsx`（带 `"use client"`），详情页（Server Component）导入后调用会拿到 client reference，构建时报
> `TypeError: (0, _._6) is not a function`。
> **解法**：把纯函数下沉到 `lib/` 下的普通模块，客户端组件再从 lib 导入。
