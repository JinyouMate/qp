# 第 9 步 · 后台管理使用说明

> 后台地址：`https://yourdomain.com/admin`
> **不进导航、不被收录**（robots.txt 已 `Disallow: /admin`）

---

## 1. 登录

1. 打开 `/admin`
2. 输入 `ADMIN_TOKEN`（就是 `.env.local` / Vercel 环境变量里设的那个值）
3. 口令会存在浏览器 localStorage（`qipei_admin_token`），下次自动填充

**口令未设置时**：接口返回 401，页面提示未配置。去环境变量设一个强随机串：

```bash
openssl rand -hex 32
```

> 换口令后，之前登录过的浏览器会自动登出（旧 token 失效）。

## 2. 看板（页面上半部分）

### 2.1 四个 KPI 卡

| 卡片 | 含义 | 怎么用 |
|---|---|---|
| 线索总数 | 当前筛选范围内的留资条数 | 看大盘 |
| 今日留资 | 今天（北京时间）新增 | 每天必看 |
| **高质量线索占比** | 填了「具体问题描述」的比例 | 这个数低说明表单引导有问题 |
| 加微点击 | `wechat_click` 事件数 | 与线索数对比，看中间漏在哪 |

### 2.2 每日留资柱状图

最近 30 天，按北京时间补零（没留资的日子显示 0，不会断档）。
**看趋势**：内容发布后是否有峰值 → 判断哪种内容带来线索。

### 2.3 事件漏斗

```
访问 → 加微点击 → 表单提交 → 第三方跳转
```
以「线索数（表单提交）」为分母算转化率。

**怎么读**：
- 加微点击 ≫ 表单提交 → 拦截弹窗劝退太多，或表单太长
- 第三方跳转很少 → 付费产品吸引力不足，或价格没讲清
- 某天事件暴涨但线索没涨 → 可能是自己人测试或刷量

### 2.4 事件计数表

各事件的原始计数，用于核对埋点是否正常工作。

### 2.5 演示模式

**未配置 Supabase 时**，接口返回标注为「演示数据」的样本，看板能正常预览形态。
页面顶部会有明确提示，**不会把演示数据误当真实数据**。接上库后自动切真实数据。

## 3. 线索表（页面下半部分）

### 3.1 时间范围（用于每周导出）

快捷按钮：**本周**（默认）/ 上周 / 近 7 天 / 本月 / 自定义（起止日期）

### 3.2 筛选

按 **身份**（修理厂/汽配商/平台企业/AI公司/其他）、**需求**（8 项）、**来源渠道**（8 项）组合筛选。

### 3.3 表格字段

| 列 | 说明 |
|---|---|
| 时间 | 提交时间（北京时间） |
| 姓名 / 联系方式 | 用户填的微信或手机 |
| 身份 / 需求 | 下拉选择项 |
| 渠道 | 自动归类：抖音/视频号/知乎/公众号/B站/搜索/直接访问/其他 |
| 描述 | 具体问题描述（有内容的优先跟进） |
| 状态 | `new` 新线索 / `contacted` 已联系 / `won` 成交 / `closed` 关闭 |

### 3.4 统计区

筛选后自动给出三张分布表：**按身份 / 按需求 / 按来源渠道** + **身份 × 需求交叉表**。
交叉表用来发现「哪类人最想要什么」，直接决定下一步做什么内容。

## 4. 导出 CSV

点「导出当前范围 CSV（N 条）」→ 下载 `leads-<起始>_<结束>.csv`。

- 带 **UTF-8 BOM**，Excel 双击打开不乱码
- 含 `channel_label` 列（渠道中文名）
- 只包含当前筛选范围与筛选条件的数据

### 命令行导出（可挂定时任务）

```bash
curl -H "x-admin-token: <ADMIN_TOKEN>" \
  "https://yourdomain.com/api/admin/leads?from=2026-10-06&to=2026-10-12&format=csv" \
  -o leads-2026-10-06_2026-10-12.csv
```

> 已建**每周一 09:00 的自动化**：自动导出上周线索 + 产出分类简报（环比、主力渠道、一条可执行建议），CSV 落到 `leads-export/`。未配置 Supabase 时会自动跳过而不编造数据。

## 5. 线索状态流转

后台页面**只读**展示状态，改状态去 **Supabase → Table Editor → leads** 直接改，或用 SQL：

```sql
-- 标记为已联系
update public.leads set status = 'contacted' where id = 123;

-- 批量：某天之前的新线索统一关闭
update public.leads set status = 'closed'
where status = 'new' and created_at < now() - interval '30 days';
```

建议流程：**当天新线索当天联系 → 改 contacted → 成交改 won → 明确无意向改 closed**。

## 6. 常用 SQL（Supabase SQL Editor 直接跑）

```sql
-- 最近 7 天每日留资
select date_trunc('day', created_at)::date as day, count(*)
from public.leads
where created_at > now() - interval '7 days'
group by 1 order by 1;

-- 各渠道线索数与高质量占比
select channel,
       count(*) as total,
       round(100.0 * count(*) filter (where coalesce(description,'') <> '') / count(*), 1) as qualified_pct
from public.leads group by channel order by total desc;

-- 身份 × 需求 交叉
select role, demand, count(*) from public.leads group by 1,2 order by 3 desc;

-- 重复线索（同联系方式多次提交）
select contact, count(*) from public.leads group by contact having count(*) > 1;

-- 事件漏斗
select event, count(*) from public.events group by event order by 2 desc;
```

## 7. 安全建议

1. `ADMIN_TOKEN` 用 `openssl rand -hex 32` 生成，不要用生日、手机号
2. 不要把 `/admin` 链接发给别人；换人时改 token 即可全部登出
3. 线索含个人联系方式，**导出文件不要发群里**；统计口径可分享，原始数据不外传
4. 定期清理：超过 6 个月且无意向的线索可归档导出后删除
5. Supabase 后台开启 **2FA**，service_role key 只放在服务端环境变量

## 8. 出问题怎么查

| 现象 | 排查 |
|---|---|
| 登录一直失败 | 环境变量 `ADMIN_TOKEN` 是否设置；改了要 Redeploy；浏览器 localStorage 里是不是旧值（清一下） |
| 看板显示「演示数据」 | Supabase 环境变量没生效，检查 `NEXT_PUBLIC_SUPABASE_URL` 与 `SUPABASE_SERVICE_ROLE_KEY` |
| 有线索但看板为空 | 时间范围是不是选了没有数据的区间；先把范围清空 |
| 导出 CSV 是空的 | 当前筛选条件下无数据，放宽范围 |
| 渠道全是「其他」 | 入站链接没带 utm_source，或 referrer 被平台抹掉了，可以在链接里显式带 `?utm_source=zhihu` |
| 某个事件一直是 0 | 检查对应组件是否用了 `TrackedLink`/`trackEvent`；GA4 与自建库是两套，看板读的是自建 `events` 表 |
